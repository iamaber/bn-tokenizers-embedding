# Sources affecting the improvement plan — 9 October 2026

This targeted follow-up reads [LITERATURE_SOURCE_CHECK.md](LITERATURE_SOURCE_CHECK.md) first and checks only sources that change practical priorities. It does not repeat the complete literature audit. Recommendations below are inferences for this project, not results established for Bengali retrieval.

| Resource | Verified evidence | Practical implication |
|---|---|---|
| BanglaDual | The deposit is dated 3 July 2026, labels itself CC BY 4.0, and contains 1,122,189 Banglish–Bangla pairs plus 119,727 Banglish–English pairs. Its 1,122,998-row merged file is an **outer join**, not a complete-triple dataset. Wikipedia contributes 85.34%; BanglaTLit appears among related resources. Deduplication is exact-pair based, and published splits are random. [Dataset metadata and reproduction steps](https://data.mendeley.com/datasets/pxw2bb4wyt/1) | Use it as a candidate training resource after inspecting complete-case counts, upstream provenance and duplicate groups. Rebuild splits by source/semantic group; a random split does not establish independence from project Wikipedia data or BanglaTLit. Do not promise a million three-way evaluation examples. |
| BanglaTLit | The authors' repository states that its **42,705 aligned pairs are a subset of the 245,727-sample BanglaTLit-PT corpus**. It also provides further-pretrained encoder weights. The paper reports classification and back-transliteration, not retrieval. [Author repository](https://github.com/farhanishmam/BanglaTLit), [paper](https://aclanthology.org/2024.findings-emnlp.859/) | Remove held-out aligned groups from PT adaptation as well as from contrastive training. Do not assume the further-pretrained checkpoint is clean for BanglaTLit evaluation. Transliteration pairs help evaluate alignment; they do not replace human-written search queries with relevance judgments. |
| FIRE CMIR-2025 | The organizer overview reports 107,900 documents, 20 training queries and 30 test queries. Training queries are predominantly Romanized; test queries mix Bengali and Roman scripts. Unlike 2024, native Bengali is retained. The best system uses classical lexical rank fusion, obtaining MAP 0.2118. [Organizer overview, §§4–6](https://ceur-ws.org/Vol-4173/T3-1.pdf) | Specify the edition. Add it as an external mixed-script check, with uncertainty reported because query count is small. Include BM25 and a sparse+dense fusion reference when judging practical search quality. Keep a separate pure-encoder comparison for the tokenizer hypothesis. |
| FOCUS | The main adaptation experiment uses **12.8B tokens** on XLM-R and evaluates NLI, QA and NER. Replacement wins on average; retaining the original vocabulary wins for German. It learns auxiliary token embeddings from unlabeled target-language data. [Paper, §§3.2–4](https://arxiv.org/html/2305.14481) | FOCUS is a plausible initialization candidate, not evidence of affordable Bengali retrieval gains. Measure initialization cost, representation loss immediately after swapping, and recovery versus budget. Keep the original-tokenizer adaptation control. |
| ZeTT | XLM-R transfer is evaluated on XNLI across 14 languages, excluding Bengali. Its **800M-token continued-training table concerns decoder models**: Mistral's natural-language average recovers from 73.0 to 74.9 versus 76.9 originally; code recovers from 23.2 to 27.6 versus 28.1. [Paper, Tables 1–2](https://arxiv.org/html/2405.07883) | Do not transfer the “under 1B tokens” recovery claim into a Bengali retrieval budget. Use a small staged recovery experiment before committing to a full swap. Count any newly trained hypernetwork as part of project cost. |

The sources support the order **finish trustworthy evaluation → adapt the existing tokenizer on clean alignment data → compare one initialized tokenizer swap**. They do not justify training an encoder from scratch as the next step, nor establish that a dedicated tokenizer will improve retrieval. Report both equal-data results and measured compute because changing tokenization changes sequence lengths and the text represented by a token budget.
